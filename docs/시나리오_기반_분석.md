좋아. 이제 **시나리오 기반 분석**을 진행한다. 이 단계의 목적은 기능을 다시 설명하는 게 아니라, 실제 플레이 상황에 요구사항을 넣어 보면서 **상태 전이, 예외 상황, 누락된 규칙**을 찾는 것이다.

# 1. SCN-01 — 신규 플레이어의 성장과 최초 왕 탄생

### 시작 상태
- 신규 플레이어 A가 서버에 접속한다.
- 서버는 A를 Steam ID로 식별한다.
- A의 개인 세력 `A`가 생성된다.
- 세력 Tier는 `Tribe`.
- A는 아직 왕이 아니다.
- Tribe는 다른 플레이어를 가입시킬 수 없다.

### 정상 흐름

`신규 유저 → 개인 Tribe → 정착지 성장 → 승격 조건 만족 → Minor Faction + King`

1. A가 최초 정착지를 건설한다.
2. 정착지/Wealth/폰/연결영토 등의 수치가 증가한다.
3. 서버가 Tier 승격 조건을 반복 평가한다.
4. Minor Faction 승격에 필요한 모든 조건을 충족한다.
5. 서버가 하나의 원자적 사건으로:
   - Tier를 `Tribe → Minor Faction`으로 변경한다.
   - A를 `King`으로 승격한다.
6. A에게 승격 Letter를 표시한다.
7. 세력명 변경 Dialog를 한 번 표시한다.
8. A가 이름을 변경하거나 기존 이름을 유지한다.
9. 이제 A는 다른 플레이어를 가입시킬 수 있다.

### 대안 흐름
승격 조건 일부만 만족한 경우에는 승격하지 않고 UI에서 정확한 진행도를 보여준다.

예:

`정착지 2/3 / Wealth 78,000/100,000 / 연결영토 14/15`

### 파생 요구

**DER-01** Tier 평가 작업은 서버 권한이어야 한다.

**DER-02** `Minor Faction 승격`과 `최초 King 생성`은 중간 상태가 존재하지 않는 원자적 처리여야 한다.

즉,

> Minor Faction인데 King이 없는 상태

가 발생하면 안 된다.

# 2. SCN-02 — 플레이어의 다른 세력 가입

A는 독립 세력이고 B는 King이다.

### 정상 흐름

1. A가 B 세력에 가입 신청한다.
2. B에게 가입 요청이 표시된다.
3. B가 수락한다.
4. B는 A에게 부여할 작위를 지정한다.
5. 최소 작위는 Baron이다.
6. 봉건 계통도 지정한다.
7. 서버가:
   - A의 기존 개인 Faction을 해체한다.
   - A의 정착지들을 B Faction으로 이전한다.
   - A에게 지정된 작위를 부여한다.
   - Feudal Tree에 A를 삽입한다.
8. A의 기존 세력 색상은 사용 가능 색상 Pool로 반환된다.
9. 국경 및 내부 작위령을 다시 계산한다.

### 실패 흐름

B가 가입을 거절한다.

→ 아무 상태도 변경되지 않는다.

### 새로 발견된 중요 예외

A가 독립 당시 정착지를 4개 가지고 있다고 하자.

그런데 B가 A에게 Baron을 주고, Baron의 최대 정착지 한도가 2라면 문제가 생긴다.

따라서 가입 Transaction에는 다음 검증이 필요하다.

> **부여될 작위의 SettlementLimit ≥ 가입 플레이어의 현재 SettlementCount**

그렇지 않으면 최소한 다음 중 하나가 필요하다.

- 더 높은 작위를 부여
- 가입 전에 초과 정착지 양도
- 가입 Transaction 내에서 동시에 양도

이것은 기존 인터뷰에서 명시되지 않았던 **새로운 요구 공백**이다.

# 3. SCN-03 — 작위 승진과 강등

공작 A가 왕 B의 봉신이라고 가정한다.

### 승진

`Count → Marquess`

1. B가 관리 UI에서 A를 선택한다.
2. 승진 명령을 선택한다.
3. 새 작위를 지정한다.
4. 서버가 권한을 검증한다.
5. 기존 작위를 제거하고 새 작위로 대체한다.
6. SettlementLimit과 작위령 Radius가 재계산된다.
7. 내부 영토 지도가 갱신된다.

### 강등

`Duke → Count`

현재:

`SettlementCount = 5`

새 Count Limit:

`3`

이라면 바로 강등할 수 없다.

### 강등 Transaction

1. 왕이 강등을 요청한다.
2. 서버가 새로운 SettlementLimit을 계산한다.
3. `5 > 3`이므로 정착지 2개를 양도해야 함을 표시한다.
4. 대상 플레이어가 양도할 정착지를 선택한다.
5. 선택한 정착지를 King/Emperor에게 이전한다.
6. 소유권 이전 성공 여부를 확인한다.
7. 이후에만 작위를 Duke → Count로 변경한다.

### 파생 요구

정착지 양도와 작위 변경 중 하나가 실패하면 전체 작업을 롤백해야 한다.

즉 강등은 **원자적 비즈니스 Transaction**이다.

# 4. SCN-04 — 작위 박탈 / 세력 제명

A는 B왕국의 백작이다.

1. B가 A의 작위를 박탈한다.
2. 서버가 A의 SettlementLimit을 독립 세력 기준으로 다시 계산한다.
3. 초과 정착지가 존재하면 먼저 B에게 양도한다.
4. 이후:
   - A의 작위를 제거한다.
   - A를 B Faction에서 제거한다.
   - A의 새로운 개인 Faction을 생성한다.
   - 남아 있는 정착지를 신규 Faction에 귀속한다.
5. 보유 자산을 기준으로 새로운 Tier를 계산한다.
6. 새로운 세력색을 자동 지정한다.
7. 국경과 외교 상태를 갱신한다.

여기서 중요한 규칙은:

> **Title Revocation = Faction Expulsion**

이다.

# 5. SCN-05 — 정찰과 매복

A와 B는 적대 가능성이 있는 서로 다른 세력이다.

### 정찰

1. A Caravan이 일반 타일에서 정지한다.
2. A가 `정찰` Gizmo를 선택한다.
3. Caravan이 Scout 상태가 된다.
4. Shooting 최고 Pawn을 기준으로 기본 시야를 계산한다.
5. Scout Bonus를 더한다.
6. A Faction 전체에 해당 Vision을 공유한다.
7. A의 Alliance에도 Vision이 공유된다.

Scout는 시간 제한 없이 지속된다.

### 정찰 종료

1. A가 이동 명령을 내린다.
2. Scout 상태를 해제한다.
3. Movement Lock Timer가 시작된다.
4. Timer가 끝날 때까지 이동 불가.
5. 이후 Traveling으로 전환.

### 공격받은 경우

`Scout → 즉시 해제 → Tactical Session`

---

## 매복 흐름

1. B Caravan이 상대 Vision 밖에 있다.
2. B가 Ambush를 선택한다.
3. B는 이동 불가 상태가 된다.
4. 상대 세력이 Vision 범위로 접근하면 탐지 판정을 수행한다.

탐지 요소:

`Observer 최고 Shooting + Ambush Caravan 전체 개체 수 + 서버 설정 계수`

### 탐지 성공

A가 B를 발견한다.

→ B는 A Faction에게 Ambush 종료까지 계속 표시된다.

그리고 A의 동맹도 그 탐지 결과를 공유한다.

### 탐지 실패

A에게는 B가 보이지 않는다.

다른 Faction C는 별도 확률로 다시 판정한다.

### 중요한 점

매복은 **전투 보너스를 제공하지 않는다.**

오직 전략 지도상의 위치 은폐 기능이다.

# 6. SCN-06 — 평화 방문

A의 Caravan이 B의 Settlement에 도착한다.

B는 온라인 상태다.

1. A가 Settlement를 선택한다.
2. `방문 요청`을 누른다.
3. B에게 Entry Request가 전달된다.
4. A에게 Waiting Dialog가 표시된다.
5. B가 승인한다.
6. B Settlement Map을 기반으로 Tactical Session이 생성된다.
7. A의 Pawn이 맵에 진입한다.

조작권:

- A → A Pawn
- B → B Pawn

### 시간 조작

A: 3x 선택

→ 전체 맵 3x.

이후 B: Pause

→ 전체 맵 Pause.

즉:

> **Last Speed Input Wins**

# 7. SCN-07 — 방문 요청 취소

B가 아직 승인하지 않았다.

1. A가 Waiting Dialog에서 Cancel을 누른다.
2. Visit Request가 취소된다.
3. B의 요청도 무효화된다.
4. A Caravan의 이동 Lock이 해제된다.
5. A는 다시 월드맵 이동 가능.

B가 취소 이후 늦게 Accept 패킷을 보내더라도 서버는 Request ID 상태를 검사하여 거부해야 한다.

따라서 Visit Request에는 최소:

`RequestId + RequestState`

가 필요하다.

# 9. SCN-09 — 방문 중 절도

A가 B 정착지를 평화 방문 중이다.

A가 B의 물건을 가져간다.

현재 요구상 **행위 자체를 차단하지 않는다.**

즉 WarEconomy의 설계 원칙은:

> 플레이어가 나쁜 행동을 못 하게 막는 것이 아니라 행동의 결과를 게임 시스템에 반영한다.

이다.

다만 여기서 새로 발견되는 부분이 있다.

**절도가 어느 순간부터 Betrayal인가**는 아직 정확하게 정의되지 않았다.

예:

- 물건을 집는 순간?
- Map 밖으로 가지고 나가는 순간?
- 소유권이 변경되는 순간?

이것은 이후 유스케이스 전에 정책을 하나 정해야 한다.

# 10. SCN-10 — 평화 방문 중 배신

10. A의 다른 Alliance는 유지한다.
11. 정상적인 RimWorld 전투로 계속 진행한다.

방문 세션을 종료하고 전투 세션을 새로 생성하지 않는다.

# 11. SCN-11 — 아군 오사

A와 B가 C를 상대로 함께 싸우고 있다.

A가 C를 사격한다.

총알이 빗나가 B를 맞힌다.

판정:

`IntendedTarget = C`

이므로 Betrayal 아님.

이상적인 AoE도 같은 원리를 따른다.

A가 C에게 수류탄을 던졌는데 B가 폭발에 맞음:

→ Betrayal 아님.

A가 B를 직접 목표로 광역 공격:

→ Betrayal.

이 추적이 기술적으로 지나치게 어렵다면 모든 AoE를 Betrayal 판정에서 제외하는 fallback을 허용한다.

# 12. SCN-12 — 정식 선전포고

A국가의 최고 작위자가 B국가에 전쟁을 선언한다.

### 선전포고 순간

1. 서버가 A가 Faction Ruler인지 검증.
2. 같은 B에 대한 PostWarCooldown 여부 확인.
3. War Declaration 생성.
4. A Tier를 기반으로 WarPending Duration 계산.
5. 관계:

`Neutral → WarPending`

6. B에게 Letter 발행:
   - 공격 Faction
   - 남은 대기시간
   - 전쟁 시작 예정시간
7. A에게 선언 확인 Letter 발행.
8. B 영토 안의 A Caravan을 즉시 퇴거시킨다.

### Pending 중

A → B 공격 불가.

B → A 공격도 불가.

### Timer 종료

`WarPending → War`

이후 양측 모두 정식 공격 가능.

# 13. SCN-13 — 하급 귀족의 독단 공격

A왕국의 Count C가 왕의 허락 없이 B세력을 공격한다.

1. C가 B의 Caravan 또는 Settlement를 공격한다.
2. 정식 War Declaration은 존재하지 않는다.
3. 공격은 시스템적으로 허용한다.
4. 즉시:
   - A Faction ↔ B Faction = Hostile/War
   - A Faction = Betrayer
5. A왕 역시 C의 행동 결과를 감수한다.

이것은 WarEconomy의 정치 시스템에서 중요한 특징이다.

> 하위 플레이어의 행동이 세력 전체에 외교적 책임을 발생시킨다.

# 15. SCN-15 — 동맹의 전쟁 자동 참전

# 19. SCN-19 — 오프라인 정착지 침공

B가 Offline이다.

A는 B와 정식 War 상태다.

1. A가 B Settlement에 공격 명령.
2. Visit와 달리 Offline 여부가 공격을 막지 않는다.
3. B Settlement Map이 전투 가능한 상태로 로드된다.
4. B측 Pawn은 AI가 조작한다.
5. A는 자기 Pawn을 직접 조작한다.
6. 전투 결과를 B의 실제 Settlement Save에 반영한다.
7. B가 나중에 접속하면 공격받았다는 Letter가 표시된다.

### 전투 도중 B 접속

선호 방향:

`AI Control → Player B Control`

로 전환한다.

### 핵심 아키텍처 Gap

현재 기술 후보는:

> Map Owner Client가 Authority

인데 B가 Offline이다.

따라서 이 시나리오는 나중에 반드시 별도의 Authority 전략이 필요하다.

이것은 현재 프로젝트의 **가장 큰 기술 리스크 중 하나**다.

# 20. SCN-20 — 전투 승리 후 정착지 점령

A가 B Settlement의 모든 적대 Entity를 제거한다.

Victory Dialog:

- 점령
- 파괴

### 점령

서버는 먼저:

`A SettlementCount < A SettlementLimit`

인지 확인한다.

가능하면:

- Settlement Owner → A
- Faction → A Faction
- Buildings → A
- Items → A
- Animals → A
- Surviving Pawns → A

로 소유권을 원자적으로 변경한다.

국경도 재계산한다.

# 21. SCN-21 — 정착지 파괴

A가 Destroy를 선택한다.

1. A가 Caravan을 구성한다.
2. Caravan이 Settlement Map에서 출발한다.
3. B Settlement 제거.
4. 해당 Settlement Border 즉시 제거.
5. 임시 Ruins Site 생성.
6. RuinsDuration 경과.
7. Site 제거.

# 22. SCN-22 — 왕의 핵심 영토 붕괴

King A에게 두 Duke Branch가 있다고 한다.

```text
King A
 ├─ Duke B
 └─ Duke C
```

A가 정착지를 모두 잃었지만 A Caravan이 살아 있다.

→ Faction은 해체되지 않는다.

Tier만 다시 평가한다.

반면 A의 플레이어/Caravan까지 완전히 제거되어 최고 통치 Branch가 사라진다면 하위 Branch들을 분리해야 한다.

```text
Duke B Branch → Independent Faction
Duke C Branch → Independent Faction
```

각자 보유 규모를 다시 평가한다.

조건을 만족하면 새로운 King이 생성될 수 있다.

# 23. SCN-23 — 세금 설정

King A → 직속 Duke B.

A가 B에게 다음 Tax Policy를 설정한다.

`Steel ×500 / 10 World Days`

B는 자신의 UI에서:

- 요구 물품
- 수량
- 징수주기

를 미리 볼 수 있다.

세금 주기는 Settlement Time이 아닌 **World Time** 기준이다.

# 24. SCN-24 — 정상 세금 징수

세금 납부 가능일은 Day 10이다.

Tax Caravan은 Day 13에 B Settlement에 도착했다.

1. `세금 징수` Gizmo 활성화.
2. Entry Request 없이 거래형 Tax UI를 연다.
3. Steel 500을 가져간다.
4. 징수 완료.
5. 다음 징수 가능일:

`Day 13 + 10 = Day 23`

이다.

즉 예정일 기준이 아니라:

> **Actual Collection Time 기준**

이다.

# 25. SCN-25 — 세금 부족과 강제징수

요구 세금:

`Steel ×500`

실제 재고:

`Steel ×300`

부족:

`Steel ×200`

현재 Vanilla Market Value 기준:

`200 Steel = 가치 380`

이라고 가정한다.

Tax Caravan은:

- Steel 300
- 추가 재산 최대 Value 380

을 강제로 가져갈 수 있다.

봉신은 대체재를 선택할 권리가 없다.

---

# 26. SCN-26 — 체납 누적

강제징수 가능한 자산이 충분하지 않다.

부족 가치:

`500`

Tax Caravan이 이를 `Delinquency = 500`으로 기록한다.

다음 징수 때:

`현재 세금 가치 + 체납 500`

까지 강제징수 가능하다.

체납이 1,400으로 증가했고 Pawn 가치가 1,300이라면 해당 Pawn도 징수 가능하다.

Delinquency는 Settlement가 아니라 **Player에 귀속**된다.

---

# 27. SCN-27 — Tax Caravan이 오지 않음

세금 예정일이 지났지만 상위 귀족이 Tax Caravan을 보내지 않았다.

결과:

**아무 일도 일어나지 않는다.**

- 자동 체납 없음
- 자동 납부 없음

실제 Tax Caravan의 징수 시도가 있어야만 세금 이벤트가 발생한다.

---

# 28. SCN-28 — 오프라인 자동 판매

B는 다음 판매 설정을 했다.

`Steel / Price 3 / 등록수량 100`

하지만 실제 Settlement에 30개만 있다.

B는 Offline.

A Caravan이 도착한다.

Auto Shop에는:

`Steel ×30`

만 표시된다.

A가 20개 구매한다.

결과:

- A Caravan: Steel +20
- B Settlement: Steel -20
- B Settlement: 대금 증가

B가 접속하면 거래 Letter를 받는다.

Letter 클릭 시 거래 결과가 Spawn된 위치로 카메라 이동.

# 29. SCN-29 — 오프라인 자동 매입

B가:

필요 Silver:

`1,000`

실제 Settlement Silver:

`300`

이라면 거래 가능한 최대치는 Silver 300 범위다.

자금은 주문 등록 때 예약하지 않는다.

**실시간 실제 재고가 최종 권한**이다.

# 30. SCN-30 — NPC 시장 충격

NPC Settlement X에서 Component를 A가 대량 구매한다.

Key:

`(Settlement X, Component)`

의 시장 상태가 변한다.

# 31. 시나리오 분석에서 새로 발견된 요구 공백

이번 분석을 통해 기존 인터뷰에서 보이지 않던 중요한 부분이 몇 개 추가로 발견됐다.

### GAP-01 — 세력 가입 시 정착지 한도
가입자가 새 작위 한도를 초과할 경우 처리 규칙이 필요하다.

**제안되는 일관된 규칙:**  
강등/제명과 동일하게 가입 Transaction 안에서 초과 정착지를 양도하게 한다.

---

### GAP-02 — 절도와 배신 발생 시점
절도를 허용한다고 정의했지만 언제 외교적 적대행위가 되는지는 아직 없다.

예를 들어 물건을 집는 즉시인지, 맵 밖으로 가지고 나갈 때인지 정해야 한다.

---

### GAP-03 — 국경 퇴거 위치
WarPending 시작 시 적 Caravan을 즉시 퇴거한다고 했지만 **어느 타일로 이동시키는가**가 없다.

안전한 규칙은:

> 가장 가까운 공격 Faction 비소유/방어자 비영토 타일로 이동

같은 방식이 될 수 있지만 아직 확정 사항은 아니다.

---

### GAP-04 — 세금 부분 징수 후 다음 주기
Tax Caravan이 일부만 징수하고 나머지를 체납으로 남긴 경우에도 그날을 `LastCollection`으로 볼 것인지 명문화가 필요하다.

현재 문맥상 그렇게 보는 것이 가장 자연스럽다.

---

### GAP-05 — Faction 완전 소멸 조건
Settlement 0이어도 Caravan이 있으면 유지된다는 것은 확정됐다.

그러므로 최종적으로는 대략:

> Settlement = 0 AND Caravan = 0 AND 기타 생존 소유 Entity 없음

일 때 Faction이 실제 소멸하는지 확정할 필요가 있다.

---

### GAP-06 — 오프라인 전투 Authority
기능 요구가 아니라 **Architecture Blocking Issue**다.

최종 설계 단계까지 미뤄도 되지만 구현 전에 반드시 해결해야 한다.

---

# 32. 시나리오 분석 결론

지금까지의 요구를 실제 플레이 흐름에 적용해 본 결과, 전체 도메인은 서로 상당히 일관되게 연결된다.

특히 WarEconomy의 게임 디자인 핵심이 명확해졌다.

> **시스템은 플레이어의 행동을 지나치게 금지하지 않는다. 대신 행동의 정치적·경제적·영토적 결과를 서버가 강제한다.**

예를 들어:

- 평화 방문 중 물건을 훔칠 수 있음
- 동맹을 배신할 수 있음
- 하위 귀족이 왕의 허락 없이 전쟁을 일으킬 수 있음
- 세금을 내지 못할 수 있음

하지만 그 결과로:

- Betrayer
- Faction-wide War
- Delinquency
- Title Revocation
- Territory Loss

등이 발생한다.

이 원칙은 이후 요구명세의 **상위 설계 원칙**으로 넣는 것이 적합하다.
