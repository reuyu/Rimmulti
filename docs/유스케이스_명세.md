
# WarEconomy 유스케이스 명세 v1

## 0. 공통 액터

- **Player**: 일반 플레이어
- **Faction Ruler**: 해당 세력의 최고 작위 보유자
- **King / Emperor**: 작위 관리 권한을 가진 통치자
- **Vassal**: 봉건 계통에 소속된 플레이어
- **Settlement Owner**: 정착지 소유자
- **Caravan Owner**: 캐러밴 소유자
- **Dedicated Server**: 월드 상태 및 게임 규칙의 중앙 권한
- **NPC Settlement**: NPC 거래 주체
- **Defending AI**: 오프라인 방어자 대신 폰을 조종하는 AI
- **Server Administrator**: 서버 콘솔 운영자


# UC-01 서버 접속 및 플레이어 인증

**Primary Actor:** Player  
**Supporting Actor:** Dedicated Server

### Trigger
플레이어가 WarEconomy 서버에 접속한다.

### Preconditions
- WarEconomy 클라이언트 모드가 설치되어 있어야 한다.
- 서버가 실행 중이어야 한다.

### Main Flow
1. 클라이언트가 서버에 접속을 요청한다.
2. 클라이언트와 서버가 프로토콜/모드 버전을 교환한다.
3. 서버가 버전 호환성을 검증한다.
4. 서버가 플레이어의 Steam ID를 확인한다.
5. 등록된 Player가 존재하면 기존 Player 상태를 불러온다.
6. 신규 사용자라면 새로운 Player를 생성한다.
7. 신규 Player에게 개인 Faction을 생성한다.
8. 초기 Faction Tier를 `Tribe`로 설정한다.
9. 사용 가능한 Faction Color를 자동 배정한다.
10. 플레이어를 World에 접속시킨다.

### Alternative Flow
Steam ID 기반 인증을 구현하기 어려울 경우 ID/Password 기반 인증을 사용할 수 있다.

### Exception Flow
- 클라이언트와 서버 버전이 맞지 않으면 접속을 거부한다.
- Ban 상태인 Player는 접속을 거부한다.

### Postconditions
- Player가 서버에서 고유하게 식별된다.
- Player의 기존 또는 신규 게임 상태가 로드된다.


# UC-02 세력 Tier 승격 및 강등

**Primary Actor:** Dedicated Server  
**Interested Actor:** Faction Members

### Trigger
세력의 정착지, Wealth, 폰, 영토 연결성 등의 평가 값이 변경된다.

### Preconditions
- Faction이 존재해야 한다.

### Main Flow — 승격
1. 서버가 현재 Tier의 승격 조건을 계산한다.
2. 모든 필요 조건을 평가한다.
3. 조건이 충족되면 즉시 Tier를 한 단계 승격한다.
4. `Tribe → Minor Faction`이면 창립자를 동시에 King으로 승격한다.
5. Tier에 따른 Border Radius를 갱신한다.
6. 허용 가능한 작위 수와 관련 제한을 갱신한다.
7. 모든 구성원에게 승격을 알린다.
8. 최고 통치자에게 Faction 이름 변경 Dialog를 한 번 제공한다.
9. 이름을 변경하지 않으면 기존 이름을 유지한다.

### Main Flow — 강등
1. 서버가 강등 기준 미달을 감지한다.
2. 서버 설정의 강등 유예기간 Timer를 시작한다.
3. 유예기간 동안 조건이 복구되면 Timer를 취소한다.
4. 복구되지 않으면 Tier를 강등한다.
5. Border 및 관련 제한을 다시 계산한다.

### Business Rules
- Minor Faction 이상은 요구되는 봉건 통치 조건을 만족해야 한다.
- Empire 승격에는 Emperor 조건이 필요하다.
- 구체적인 Threshold와 공식은 서버 설정 대상이다.
- Tier 진행도는 UI에서 정확한 수치로 표시한다.

### Postconditions
Faction Tier와 그에 종속된 규칙이 최신 상태가 된다.


# UC-03 다른 세력 가입

**Primary Actor:** Joining Player  
**Secondary Actor:** Faction Ruler

### Trigger
독립 Player가 다른 Faction에 가입을 신청한다.

### Preconditions
- 대상 Faction은 최소 Minor Faction 이상이어야 한다.
- Tribe는 다른 Player를 받아들일 수 없다.
- Joining Player는 다른 Faction에 동시에 가입할 수 없다.

### Main Flow
1. Player가 가입 요청을 보낸다.
2. 대상 Faction Ruler에게 요청이 전달된다.
3. Ruler가 요청을 수락한다.
4. Ruler가 가입자에게 부여할 작위를 선택한다.
5. 최소 작위는 Baron이다.
6. 봉건 계통상의 위치를 선택한다.
7. 서버가 가입자의 기존 개인 Faction을 해체한다.
8. Player와 Player의 Settlement를 대상 Faction으로 이전한다.
9. 선택한 작위를 부여한다.
10. Feudal Tree를 갱신한다.
11. 기존 개인 Faction의 색상을 재사용 가능 상태로 반환한다.
12. Territory를 다시 계산한다.

### Alternative Flow
Ruler가 가입 요청을 거절하면 상태 변경 없이 종료한다.

### Open Issue
부여될 작위의 SettlementLimit보다 가입자의 Settlement 수가 많을 경우:
- 초과 Settlement 양도 후 가입하도록 하는 방향이 가장 일관적이나 최종 확정 필요.

### Postconditions
가입자는 기존 개인 Faction을 잃고 대상 Faction의 정식 구성원이 된다.


# UC-04 작위 임명·승진·강등·박탈

**Primary Actor:** King 또는 Emperor  
**Secondary Actor:** Target Player

### Preconditions
- Actor는 King 이상이어야 한다.
- Target은 관리 가능한 Faction/봉건 구조 내에 있어야 한다.

### Main Flow — 임명
1. Actor가 Target을 선택한다.
2. 부여할 작위를 선택한다.
3. 봉건 계통을 지정한다.
4. 서버가 권한 및 작위 수 제한을 확인한다.
5. 작위를 부여한다.

### Main Flow — 승진
1. 기존 작위를 더 높은 작위로 대체한다.
2. SettlementLimit과 Title Territory Radius를 갱신한다.

### Main Flow — 강등
1. 낮은 작위를 선택한다.
2. 새로운 SettlementLimit을 계산한다.
3. 초과 Settlement가 있으면 양도 절차를 수행한다.
4. 양도가 성공하면 작위를 대체한다.

### Main Flow — 박탈
1. 작위를 제거한다.
2. Target을 Faction에서 제명한다.
3. 필요한 초과 Settlement를 King/Emperor에게 양도한다.
4. Target에게 새로운 개인 Faction을 생성한다.
5. 남은 자산에 따라 Tier를 재계산한다.

### Business Rules
- Player는 하나의 작위만 보유한다.
- 임명·승진·강등·박탈 권한은 King 이상만 가진다.
- 작위 박탈과 Faction 제명은 동일한 결과를 가진다.
- 일반 국가의 유일한 King은 자발적으로 탈퇴할 수 없다.

### Postconditions
Feudal Tree와 Territory가 새 작위 상태와 일치한다.


# UC-05 정착지 자발적 양도

**Primary Actor:** Current Owner  
**Secondary Actor:** New Owner

### Trigger
Player가 자신의 Settlement를 다른 Player에게 양도한다.

### Preconditions
- 양수자가 해당 Settlement를 소유할 수 있어야 한다.
- SettlementLimit을 초과해서는 안 된다.

### Main Flow
1. 양도 대상 Settlement를 선택한다.
2. 새 Owner를 선택한다.
3. 서버가 양수자의 SettlementLimit을 확인한다.
4. 소유권 이전 Transaction을 시작한다.
5. Settlement Owner를 변경한다.
6. 맵 내 건물, 아이템, 동물, 폰 등의 Faction/Ownership을 새 Owner에 맞게 변경한다.
7. Territory를 재계산한다.
8. 전체 Transaction 성공을 확인한다.

### Exception Flow
중간 단계가 실패하면 변경 사항을 Rollback한다.

### Postconditions
Settlement 및 관련 Entity가 새 Owner에게 일관되게 이전된다.


# UC-06 캐러밴 정찰

**Primary Actor:** Caravan Owner

### Preconditions
- Caravan이 Settlement가 아닌 일반 World Tile에 있어야 한다.
- 전투 중이 아니어야 한다.

### Main Flow
1. Player가 `정찰`을 선택한다.
2. Caravan이 Scout 상태로 전환된다.
3. Caravan은 이동할 수 없게 된다.
4. 구성 Pawn 중 Shooting이 가장 높은 Pawn을 기준으로 기본 Vision을 계산한다.
5. Scout Bonus를 추가한다.
6. Vision 결과를 Faction과 Alliance에 공유한다.
7. Scout 상태는 사용자가 종료할 때까지 유지한다.

### Alternative Flow
Player가 Scout를 취소한다.
1. Scout 상태를 해제한다.
2. Movement Lock Timer를 시작한다.
3. Timer 종료 후 이동 가능해진다.

### Exception Flow
공격받으면 Scout 상태를 즉시 종료하고 Tactical Session에 들어간다.

### Postconditions
Caravan은 Scout 또는 Traveling 상태 중 하나에 존재한다.


# UC-07 캐러밴 매복

**Primary Actor:** Caravan Owner  
**Secondary Actor:** Detecting Faction

### Preconditions
- Caravan이 적 Faction의 현재 Vision 안에 있어서는 안 된다.
- Ambush Cooldown이 없어야 한다.

### Main Flow
1. Player가 `매복`을 선택한다.
2. Caravan이 Ambush 상태가 된다.
3. Caravan은 움직일 수 없다.
4. 적 Faction의 Vision에 탐지 가능 상황이 발생하면 탐지 판정을 수행한다.
5. 관측 Caravan의 최고 Shooting과 매복 Caravan의 전체 개체 수를 사용한다.
6. 탐지 성공 여부를 Faction별로 독립 계산한다.

### Detection Success
1. 해당 Faction에게 Ambush Caravan을 표시한다.
2. Ambush 종료 전까지 계속 표시한다.
3. 탐지 결과를 해당 Faction의 Alliance에 공유한다.

### Ambush End
1. 사용자가 Ambush를 해제한다.
2. Movement Lock을 적용한다.
3. 재매복 Cooldown을 적용한다.

### Business Rules
- 매복은 전투 보너스를 제공하지 않는다.
- 목적은 World Map상의 위치 은폐이다.

### Postconditions
Caravan의 은폐/노출 상태가 각 Faction별로 관리된다.


# UC-08 정착지 방문 요청

**Primary Actor:** Visiting Player  
**Secondary Actor:** Settlement Owner

### Preconditions
- 양측이 정식 전쟁 상태가 아니어야 한다.
- Settlement Owner가 Online이어야 한다.

### Main Flow
1. Visitor가 Settlement에 도착한다.
2. `방문 요청`을 선택한다.
3. 서버가 Entry Request를 생성한다.
4. Settlement Owner에게 요청을 전달한다.
5. Visitor에게 Waiting Dialog를 표시한다.
6. Owner가 Accept를 선택한다.
7. Settlement Map을 Tactical Session으로 사용한다.
8. Visitor Pawn을 맵에 진입시킨다.

### Alternative Flow — Reject
Owner가 Reject하면 Visitor는 World Map에 남는다.

### Alternative Flow — Cancel
1. Visitor가 Accept 이전에 Cancel한다.
2. Entry Request를 무효화한다.
3. Caravan을 자유 이동 가능 상태로 복구한다.

### Offline Flow
Owner가 Offline이면 Visit 버튼을 비활성화한다.
Tooltip으로 오프라인임을 표시한다.

### Postconditions
Accept된 경우 Visitor와 Owner가 동일 Tactical Session에 존재한다.


# UC-09 동일 타일 Tactical Session 참가

**Primary Actor:** Player  
**Supporting Actor:** Session Authority

### Trigger
방문, 공격 또는 기타 명시적 RimWorld식 행동으로 동일 Tile Map에 진입한다.

### Preconditions
- 해당 행동이 게임 규칙상 허용되어야 한다.

### Main Flow
1. 동일 Map을 모든 참가자에게 제공한다.
2. 각 Player는 자신의 Pawn만 조작한다.
3. 평화 상태에서는 모든 참가자가 속도를 조절할 수 있다.
4. 마지막으로 입력된 속도를 전체 Session이 따른다.
5. 적대 상태에서는 전체 속도를 1x로 강제한다.
6. 적대 상태에서는 Pause를 금지한다.

### Business Rules
- 방문과 전투는 동일 Tactical Session 구조를 사용한다.
- Session의 관계 상태만 Peaceful/Hostile 등으로 변한다.
- 다수의 Faction이 하나의 Session에 동시에 존재할 수 있다.

### Architecture Note
선호안은 Map Owner Authoritative + Remote Command Input + Snapshot Replication이지만 최종 구현 방식은 별도 설계 대상이다.


# UC-10 선전포고

**Primary Actor:** Faction Ruler  
**Secondary Actor:** Target Faction

### Preconditions
- Actor는 해당 Faction의 최고 작위자여야 한다.
- Target과의 PostWarCooldown이 없어야 한다.
- 기존 War 상태가 아니어야 한다.

### Main Flow
1. Ruler가 Target Faction을 선택한다.
2. `선전포고`를 실행한다.
3. 서버가 권한을 검증한다.
4. 공격 Faction Tier에 따라 WarPending 시간을 계산한다.
5. 관계를 WarPending으로 전환한다.
6. Target에게 공격 Faction, 남은 시간, 전쟁 시작 예정시각을 알린다.
7. 공격 Faction에도 선언 확인을 알린다.
8. Target 영토 안의 공격 Faction Caravan을 즉시 퇴거시킨다.
9. Pending Timer 종료 시 War 상태로 전환한다.
10. 직접 Alliance가 자동으로 전쟁 참가 상태가 된다.

### Business Rules
- Pending 중 양측 모두 공격할 수 없다.
- 자동 동맹 참전은 1-Hop까지만 적용한다.

### Open Issue
강제 퇴거 시 Caravan을 어느 Tile로 이동시킬지는 상세 규칙 확정 필요.


# UC-11 배신 처리

**Primary Actor:** Hostile-Action Initiator  
**Secondary Actor:** Dedicated Server

### Trigger
정식 War 권한 없이 다른 Faction에 의도적 적대 행동을 한다.

### Main Flow
1. 시스템이 의도적 Hostile Action을 탐지한다.
2. 공격 Faction과 피해 Faction을 Hostile/War 상태로 전환한다.
3. 공격 Faction에 Betrayer Status를 부여한다.
4. 공격자와 피해자가 Alliance였다면 해당 양자 Alliance를 즉시 파기한다.
5. 공격자의 다른 Alliance는 유지한다.
6. Betrayer 표시를 World Map에 반영한다.
7. Faction 이름에 `(배신자)` 표시를 추가한다.
8. BetrayerDuration Timer를 시작/연장한다.

### Friendly-Fire Exception
- 적을 직접 공격하다 발생한 단순 오사는 Betrayal이 아니다.
- 적 대상 AoE의 부수 피해 역시 가능하면 Betrayal에서 제외한다.
- 기술적으로 구현이 어렵다면 AoE 전체를 판정 대상에서 제외할 수 있다.

### Additional Rule
Betrayer Faction은 다른 세력이 선전포고 없이 공격할 수 있다.

### Removal
- Duration 만료 시 자동 제거
- 피해 Faction이 직접 제거 가능
- 반복 배신 시 Duration 증가

### Postconditions
공격 행동의 정치적 결과가 Faction 전체에 반영된다.


# UC-12 전쟁 종료 및 평화협정

**Primary Actor:** War Participant Faction  
**Secondary Actor:** Opposing Faction

### Preconditions
- 두 Faction이 War 상태여야 한다.

### Main Flow — 무조건 평화
1. 한쪽이 평화를 제안한다.
2. 상대가 수락한다.
3. War를 종료한다.
4. 동일 Faction에 대한 PostWarCooldown을 적용한다.

### Main Flow — 조건부 평화
1. 한쪽이 특정 물자를 조건으로 요구한다.
2. 상대가 수락한다.
3. War를 잠정 종료한다.
4. 시간 제한 의무/Quest를 생성한다.
5. 기한 내 요구 물자를 제공한다.
6. 평화를 확정한다.

### Failure Flow
조건부 평화 의무를 이행하지 않으면:
1. 즉시 War 상태로 복귀한다.
2. War Declaration Cooldown은 적용하지 않는다.

### Allied Peace
전쟁에 직접 참가한 Alliance Faction이 대신 평화협정을 체결할 수 있으며, 이 경우 본 전쟁도 종료된다.

### Postconditions
War 또는 Peace 상태가 일관되게 갱신된다.


# UC-13 정착지 침공

**Primary Actor:** Attacking Player  
**Secondary Actor:** Settlement Owner / Defending AI

### Preconditions
다음 중 하나를 만족해야 한다.
- 정식 War 상태
- 대상 Faction이 Betrayer
- 기타 공격 권한이 게임 규칙상 존재

### Main Flow
1. 공격 Caravan이 Settlement에 도착한다.
2. Visitor Approval 없이 Attack을 실행한다.
3. Settlement Map을 Tactical Session으로 연다.
4. 적대 Session으로 설정한다.
5. 속도를 1x로 강제한다.
6. Pause를 비활성화한다.
7. 공격자는 자신의 Pawn을 조작한다.
8. 방어자는 Online이면 자신의 Pawn을 조작한다.
9. 전투는 Vanilla RimWorld의 전투 및 후퇴 규칙을 따른다.

### Offline Defender Flow
1. Settlement Owner가 Offline이어도 공격을 허용한다.
2. 방어 Pawn을 AI가 조종한다.
3. 전투 결과를 실제 Settlement에 영구 반영한다.
4. Owner 재접속 시 공격받았다는 Letter를 표시한다.

### Mid-Battle Login
가능하면 AI 제어를 Player 제어로 넘긴다.

### Mid-Battle Logout
가능하면 Player 제어를 AI로 넘긴다.

### Architecture Blocking Issue
Offline Settlement를 실제로 누가 시뮬레이션할지는 설계 단계에서 반드시 해결해야 한다.


# UC-14 정착지 점령 또는 파괴

**Primary Actor:** Victorious Attacker

### Preconditions
- 공격자가 Settlement 전투에서 승리해야 한다.
- 적대 Entity가 Vanilla 승리 규칙상 더 이상 남아 있지 않아야 한다.

### Main Flow
1. 승리 Dialog를 표시한다.
2. `점령` 또는 `파괴`를 선택한다.

2. Limit을 초과하지 않으면 점령을 허용한다.
3. Settlement Owner를 공격자로 변경한다.
4. 건물, 아이템, 동물, 생존 Pawn 등의 Ownership을 새 Owner로 이전한다.
5. Territory를 갱신한다.

### Destroy Flow
1. 공격자가 Caravan을 구성한다.
2. 공격자가 Settlement를 떠난다.
3. Settlement를 제거한다.
4. Border를 즉시 제거한다.
5. Ruins Site를 생성한다.
6. 설정된 기간 후 Ruins Site를 제거한다.

### Exception
SettlementLimit을 초과하면 Occupy를 선택할 수 없다.

# UC-16 Tax Caravan 세금 징수

**Primary Actor:** Superior Noble / Tax Caravan  
**Secondary Actor:** Taxed Player

### Preconditions
- 유효한 Tax Policy가 존재해야 한다.
- Tax Caravan이 대상 Settlement에 도착해야 한다.

### Main Flow
1. `세금 징수` 행동을 선택한다.
2. 일반 방문 승인 없이 Tax UI를 연다.
3. 현재 요구 Item과 Quantity를 표시한다.
4. 대상 재고에서 지정 Item을 우선 징수한다.
5. 지정 Item이 부족하면 부족량의 Vanilla Market Value를 계산한다.
6. 징수자가 그 가치 이하의 다른 자산을 선택하여 강제 징수할 수 있다.
7. 납부가 완료되면 세금을 완납 처리한다.
8. 실제 징수 시점을 LastCollection으로 기록한다.
9. 다음 징수 가능 시점은 LastCollection + TaxCycle로 계산한다.

### Offline Flow
Settlement Owner가 Offline이어도 동일하게 세금 징수가 가능하다.

### Business Rules
- 대체 자산 선택권은 납세자가 아닌 징수자에게 있다.
- 징수 가능 자산에는 조건을 만족하면 사람, 노예, 동물 등이 포함될 수 있다.


# UC-17 세금 체납 처리

**Secondary Actor:** Dedicated Server

### Trigger

### Main Flow
1. 미징수된 가치를 계산한다.
2. Player의 TaxDelinquentValue에 추가한다.
3. Player에 Tax Delinquent 상태를 표시한다.
4. 다음 Tax Caravan 방문 때 현재 세금과 누적 체납 가치를 합산한다.
5. 징수자는 합산 한도 이내의 자산을 강제 징수한다.

### Business Rules
- Delinquency는 Settlement가 아니라 Player 단위이다.
- Tax Caravan이 오지 않은 것은 체납이 아니다.
- 실제 징수 시도 후 부족분이 발생해야 체납이 된다.

### Open Issue
부분 징수 후에도 해당 날짜를 LastCollection으로 처리할지 최종 명문화 필요.

# UC-19 플레이어 간 거래

**Primary Actor:** Visiting Player  
**Secondary Actor:** Settlement Owner 또는 Auto Shop

### Preconditions
- Caravan이 거래 가능한 Settlement에 도착해야 한다.

2. 현재 가능한 수량만 Visitor에게 표시한다.

- Auto Shop 이용 가능
- 직접 Vanilla식 바터 거래도 가능

# 공통 비즈니스 규칙

## BR-01 단일 Faction 원칙
Player는 동시에 하나의 Faction에만 정식 소속될 수 있다.

## BR-02 단일 작위 원칙
Player는 동시에 하나의 봉건 작위만 보유한다.

## BR-03 Tribe 단독성
Tribe는 복수 Player Faction이 될 수 없다.

## BR-04 최초 왕 생성
Tribe가 Minor Faction으로 승격되는 순간 창립자가 King이 된다.

## BR-05 왕 이상 작위 관리권
작위 임명·승진·강등·박탈은 King 이상만 수행한다.

## BR-06 직속 봉신 과세
세금은 Feudal Tree의 직속 하위 Vassal에게만 부과할 수 있다.

## BR-07 Faction 단위 외교
전쟁, 동맹, 배신자 상태 등 외교 결과는 개별 Player가 아니라 Faction 전체에 적용된다.

## BR-08 행동 자유와 결과 책임
WarEconomy는 가능한 경우 Player의 적대적 행동 자체를 차단하기보다 정치적·경제적 결과를 발생시키는 것을 우선한다.

## BR-09 공개 Settlement 정보
Settlement 위치, Faction, Owner, Tier, Border 정보는 Vision 밖에서도 최신 상태로 공개한다.

## BR-10 Caravan 은폐
Vision 기반으로 숨겨지는 핵심 World Object는 Caravan이다.

## BR-11 Faction/Alliance Vision 공유
Vision은 Faction 단위로 공유되며 Alliance에도 공유된다.

## BR-12 선점 Territory 우선
Border 확장 충돌 시 먼저 존재한 Territory가 우선한다.

## BR-13 Offline 방문 금지
Offline Settlement에는 일반 Visit Request를 보낼 수 없다.

## BR-14 Offline 공격 허용
정당한 공격 권한이 있으면 Offline Settlement도 침공할 수 있다.

## BR-15 Offline 거래/과세 허용
Auto Trade와 Tax Collection은 Settlement Owner가 Offline이어도 가능하다.

## BR-16 Last Input Wins
평화 Tactical Session의 속도는 가장 최근 Player의 속도 입력을 따른다.

## BR-17 전투 속도
Hostile Tactical Session은 1x 속도로 강제되며 Pause를 허용하지 않는다.

## BR-18 정착지 한도
Player의 SettlementLimit은 작위에 따라 결정되고 서버에서 설정할 수 있다.

## BR-19 강등/제명 시 초과 영지 양도
작위 변경으로 SettlementLimit을 초과하면 초과 Settlement를 Ruler에게 양도해야 한다.

## BR-20 Betrayer 공격 허용
Betrayer Faction은 타 Faction이 정식 선전포고 없이 공격할 수 있다.

## BR-21 동맹 자동참전 제한
전쟁 자동참전은 직접 Alliance 1-Hop에만 적용한다.

## BR-22 전쟁과 Faction 생존 분리
Settlement가 모두 사라져 전쟁이 종료되더라도 Caravan이 남아 있으면 Faction 자체는 존속할 수 있다.


# 현재 미해결 요구사항

유스케이스 작성 결과 최종 요구사항 명세 전에 결정해야 할 항목은 소수만 남았다.

1. **세력 가입자의 SettlementLimit 초과 처리**
   - 강등과 동일하게 초과 Settlement 양도 후 가입하도록 할지.

2. **절도에 의한 Betrayal 판정 시점**
   - 물건을 집는 순간
   - 소유권 변경 순간
   - Settlement 밖으로 반출하는 순간

3. **WarPending 시 국경 내부 Caravan의 강제 퇴거 목적 Tile 선정 방식**

4. **부분 세금 징수 시 LastCollection 처리**
   - 일부라도 징수했으면 그날부터 다음 Cycle을 계산할지.

5. **Faction 완전 소멸 조건**
   - Settlement와 Caravan이 모두 없어질 때 즉시 소멸할지,
   - 기타 생존 Pawn/Site 등을 고려할지.

6. **Offline Tactical Authority 구현**
   - 기능 요구는 확정됐지만 구현 구조는 아키텍처 단계에서 해결 필요.

이 중 1~5는 요구정책 문제이고, 6은 기술설계 문제다.

# 유스케이스 단계 결론

현재 요구는 다음 핵심 플레이 루프를 완전한 흐름으로 표현할 수 있다.

**성장**
→ Tier 승격  
→ 왕 즉위  
→ Player 영입  
→ 봉건 구조 형성  
→ Territory 확대  

**전략**
→ Caravan 이동  
→ 정찰/매복  
→ 외교/동맹  
→ 선전포고  

**상호작용**
→ 방문  
→ 거래  
→ 세금 징수  
→ 배신  

**전쟁**
→ Tactical Session  
→ 침공  
→ 점령/파괴  
→ 평화협정  

**정치적 재편**
→ 작위 승진/강등  
→ 제명  
→ 국가 붕괴  
→ 새로운 Faction 생성

따라서 WarEconomy의 핵심 시스템들이 각각 고립된 기능이 아니라 하나의 연속적인 게임 흐름으로 연결된다는 점까지 유스케이스 수준에서 확인되었다.
