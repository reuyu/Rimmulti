# Phase 3 인게임 수동 검증 체크리스트

발행: 2026-10-01 / 6차 사전 리뷰 통과 후 사용자 실기용.

각 항목은 **통과 / 실패 / 미실시**로 기록한다. 준비 환경이 없어 실행하지 못한 항목은 통과로 표시하지 않는다. 이번 절차는 방문 UI·로컬 양도·시야 및 국경 검증이며, 전체 멀티플레이 기능 완성을 판정하는 절차는 아니다.

## 준비

- [ ] 기존 세이브를 별도 이름으로 저장한 **테스트 사본**을 준비한다. 양도는 실제 폰과 건물의 세력을 바꾸므로 마지막에 시행한다.
- [ ] 최신 서버가 7777 포트로 실행 중인지 확인하고 콘솔을 볼 수 있게 둔다.
- [ ] RimWorld 1.6 실행 → 모드 메뉴에서 WarEconomyMod 활성화 확인 → 필요하면 게임 재시작.
- [ ] 옵션에서 개발자 모드 활성화.
- [ ] 메인 메뉴의 **War-Economy 멀티 접속** → IP `127.0.0.1`, Port `7777`, 식별 가능한 닉네임 입력 → 접속.
- [ ] 연결됨 표시와 서버 `[Auth] Player ... registered.` 로그 확인 → 테스트 세이브 로드.
- [ ] 기존 오류와 구분할 수 있도록 테스트 시작 시각을 기록한다. 개발자 로그 창에서 새 오류를 확인한다.

권장 실행 순서: 방문 → 안개/국경 → 사본 재로드 → 영지 양도.

## 검증 1 — 방문 기즈모와 요청·취소

### A. 1인 NPC 자동 승인

1. 하단 **월드** 화면으로 이동한다.
2. 자신의 세력이 아닌 NPC 정착지를 선택한다. 안개 때문에 아이콘이 숨겨져 있다면 해당 타일을 선택하여 검증 3의 시야 토글로 Active로 만든 뒤 다시 선택한다.
3. 선택 정보와 함께 표시되는 **방문 요청 (Visit)** 기즈모를 클릭한다.
4. **정착지 방문 승인 대기 중** 창 또는 직후 승인 메시지를 확인한다.

기대 결과:
- [ ] 바닐라 기즈모가 유지되고 방문 기즈모가 추가된다.
- [ ] 요청 발송 메시지 이후 NPC 승인 메시지가 나오고 대기창이 남지 않는다.
- [ ] 서버에 해당 요청의 `Auto-approving request` 로그가 표시된다.
- [ ] 새 예외 로그가 없다.

NPC는 즉시 응답하므로 대기창이 한 프레임 정도만 보이거나 육안으로 확인하기 전에 닫힐 수 있다. 이를 취소 버튼 실패로 기록하지 않는다. 승인 메시지 후 전술 맵이 열리는 것은 현재 구현의 기대 결과가 아니다.

기즈모와 별도로 개발자 **디버그 액션 메뉴**를 열어 `WarEconomy`를 검색하고 **[WarEconomy] Test Visit Request**를 실행한다. 동일한 요청/응답 UI 경로를 확인한다. 이 액션은 첫 번째 타 세력 정착지를 선택하므로, 선택해 둔 정착지를 대상으로 한다고 가정하지 않는다.

### B. 취소 인터랙션 — 온라인 호스트 준비 시

사전 조건: 대상 정착지 ID가 서버의 온라인 호스트 소유로 등록돼 있고, 방문자 월드에서 해당 정착지를 선택할 수 있어야 한다. 두 번째 클라이언트가 단순히 접속해 있는 것만으로 충족되지 않는다. 이 환경이 없으면 **미실시**로 기록한다.

1. 방문자: 해당 정착지 선택 → **방문 요청 (Visit)** 클릭.
2. 호스트: **외교 전령: 기지 방문 승인 요청** 창이 표시되는지 확인하고 승인/거절을 누르지 않는다.
3. 방문자: 대기창 하단 **방문 요청 취소 (Cancel)** 클릭.
4. 양쪽 화면과 서버 콘솔을 확인한다.

기대 결과:
- [ ] 방문자 대기창이 닫히고 “방문 요청을 철회했습니다” 메시지가 표시된다.
- [ ] 호스트 요청창도 닫히고 방문 취소 메시지가 표시된다.
- [ ] 서버에 `cancelled by authorized visitor` 로그가 표시된다.
- [ ] 취소 뒤 승인 메시지가 뒤늦게 나타나지 않는다.
- [ ] 재요청한 뒤 호스트가 **승인 (Accept)** 또는 **거절 (Deny)**을 누르면 방문자의 새 요청에만 결과가 반영된다.

## 검증 2 — 로컬 영지 양도와 결과 수신

1. 테스트 세이브 사본을 다시 로드하고 **정착지 로컬 맵**으로 이동한다.
2. 현재 플레이어 소속 폰·가축, 소유권이 있는 건물, 침대 배정 및 진행 중 작업을 기록한다. 방문객/동맹 폰이 있다면 그 세력도 기록한다.
3. 개발자 디버그 액션 메뉴 → `WarEconomy` 검색 → **[WarEconomy] Test Fief Transfer to Enemy/Allied Faction** 클릭.
4. 게임 메시지, 폰/건물 선택 정보, 개발자 로그와 서버 콘솔을 대조한다.

기대 결과:
- [ ] 폰의 기존 작업이 중단되고 양도 대상 세력으로 변경된다. 재개 후 새 AI 작업을 시작하는 것은 가능하다.
- [ ] 이전 플레이어 소속 가축과 세력 보유 건물이 변경된다. 원래 무소속인 일반 아이템까지 변경되는 것을 기대하지 않는다.
- [ ] 기존 침대/조련 관련 배정이 해제되고, 방문객·동맹 폰은 기존 세력을 유지한다.
- [ ] 맵 부모의 세력 변경 및 양도 완료 메시지를 확인한다. 대상은 코드가 선택한 첫 번째 비플레이어·비숨김 세력이며, 사용자가 선택하는 창은 없다.
- [ ] 서버에 `[FiefTransfer] Result received:`와 같은 TransferId/SettlementId의 `Success=True`가 찍힌다.
- [ ] 성공 경로에 새 NRE/Harmony/양도 오류가 없다.

**서버 커밋과 구분:** 이 디버그 액션은 서버 Offer/Pending 절차를 거치지 않는다. `No pending transfer found ... Ignoring.`은 이 로컬 디버그 경로에서 나올 수 있다. 결과 수신은 확인 가능하지만, 이 로그만으로 서버 소유권 이전이 성공했다고 판정하지 않는다. 서버 커밋은 별도의 정식 양도 요청에서 같은 TransferId의 `Fief Transfer CONFIRMED`와 서버 소유권 변경을 확인해야 한다.

실패가 발생하면:
- 정상 복구 메시지라면 이전 세력·침대 배정·허용구역·마스터가 실제로 돌아왔는지 확인한다.
- **일부 객체의 복구가 완료되지 않았습니다 (재동기화 필요)**가 나오면 실패로 기록하고 중단한다. 로그를 보존하고 테스트 사본을 재로드한다. 경고를 자동 재동기화 완료로 해석하지 않는다.
- 게임에서 예외를 억지로 유발할 필요는 없다. 롤백 실패 주입은 터미널 검증에서 수행했다.

## 검증 3 — 시야 토글과 2칸 국경

### A. 시야 토글

1. 월드맵에서 타 세력 정착지가 있는 **동일 타일**을 선택한다.
2. 디버그 액션 메뉴 → **[WarEconomy] Toggle Local Fog Cache**를 실행한다.
3. 메시지의 Layer/ID를 확인하고 같은 타일에 반복 실행하여 한 바퀴 순환한다.

기대 결과:
- [ ] `Unexplored → History → Active → Unexplored` 순환 메시지가 표시된다. 시작 상태에 따라 첫 전환은 달라질 수 있다.
- [ ] Active에서는 타 세력 정착지 아이콘이 표시되고 History/Unexplored에서는 실시간 객체가 숨겨진다.
- [ ] 자신의 세력 객체는 이 패치에서 항상 표시된다.
- [ ] 지형 전체가 안개로 덮이거나 History에 과거 잔상이 그려지는 것은 현재 기대 결과에 포함하지 않는다.

### B. 국경 거리 판정

1. 테스트 상단과 대상 NPC 정착지를 준비한다. 실제로 새 정착이 가능한 상단이어야 한다.
2. 같은 레이어에서 정착지 중심 타일의 이웃을 따라 **1칸**, **2칸** 떨어진 타일에 각각 상단을 이동한다.
3. 상단의 **정착(Settle)** 명령을 실행한다.
4. 다른 타 세력 국경과 겹치지 않는 **3칸** 타일에서도 대조 검사한다.

기대 결과:
- [ ] 1칸과 2칸에서 “타 세력의 국경(2타일) 이내에는 정착지를 건설할 수 없습니다!”가 표시되고 새 정착지가 생기지 않는다.
- [ ] 3칸에서는 이 모드의 국경 차단 메시지가 나오지 않는다. 다른 바닐라 조건까지 충족했다면 정착이 진행된다.
- [ ] 새 예외가 없다. 직선 거리나 이동 시간 대신 인접 타일 연결 횟수로 거리를 센다.

바닐라 제한으로 정착 버튼 자체가 비활성화되면 모드의 Prefix가 실행되지 않으므로 **모드 국경 검사 미실시**로 기록한다. 다른 레이어 지원을 확인할 환경이 있다면, 타 레이어의 동일 숫자 타일 때문에 차단되지 않는지도 별도로 기록한다.
